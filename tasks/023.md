# 6. Configuration Persistence

Implement safe configuration persistence.

Requirements:

- Validate before saving.
- Preserve existing configuration when validation fails.
- Use atomic file replacement where supported.
- Preserve reasonable file permissions.
- Avoid partially written configuration.
- Handle write failures.
- Handle concurrent modification.
- Create backups where appropriate.

Do not overwrite configuration blindly.

---

# 7. Configuration Transactions

Treat configuration updates as controlled transactions.

Conceptually:

```text
Load Current Configuration
          |
          v
Create Proposed Configuration
          |
          v
Validate
          |
          v
Preview Diff
          |
          v
Authorization
          |
          v
Persist Safely
          |
          v
Reload Daemon Configuration
          |
          v
Notify Clients
```

Do not mutate active configuration before validation succeeds.

Use revision identifiers or another reliable concurrency mechanism to prevent lost updates.

---

# 8. Configuration Reload

After a successful configuration update:

- Reload validated configuration.
- Update daemon state.
- Notify connected clients.
- Refresh workspace/service/profile/group listings.
- Preserve running service state where possible.

Do not restart the daemon unnecessarily.

Do not terminate running services simply because configuration changed.

---

# 9. Running Service Configuration Changes

A service may be running while its configuration is edited.

Define safe behavior.

For example:

- Configuration changes apply to future operations.
- Existing process state remains authoritative.
- Changes requiring restart are clearly indicated.
- Do not silently restart services.
- Do not silently stop services.

If a service is removed from configuration while running, require an explicit resolution.

Do not orphan managed processes.

# 46. Security

- Enforce policy through Application Core.
- Validate paths.
- Prevent path traversal.
- Handle symlinks safely.
- Restrict configuration file writes.
- Protect secrets.
- Reject malformed inputs.
- Prevent unauthorized repository deletion.
- Avoid arbitrary shell execution.

# 47. Concurrency

Multiple clients may attempt to edit configuration.

Use revision-based concurrency control or another reliable mechanism.

If configuration changed since the editor loaded:

- Reject stale updates.
- Display a conflict.
- Allow refresh and review.
- Do not silently overwrite newer changes.
