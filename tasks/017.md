# Task 017 — Real Workspace Integration, End-to-End Validation & Reliability

## Role

Act as a Principal Rust Engineer, Software Architect, Site Reliability Engineer, Quality Engineer, and macOS Developer Tooling Engineer.

You are implementing **Task 017 — Real Workspace Integration, End-to-End Validation & Reliability** of the Service Orchestrator project.

The goal is to validate, stabilize, and improve the existing application before introducing additional product features or preparing a release.

This is a reliability and integration task.

Do not redesign the architecture or implement unrelated features.

# 4. Initial Architecture Audit

Review the existing dependency direction.

Expected architecture:

```text
TUI ─────┐
         │
MCP ─────┼──> Local IPC ──> Shared Daemon
         │                       │
CLI ─────┘                       ▼
                          Application Core
                                 │
                          Workflow Engine
                                 │
                            Task Engine
                                 │
                  ┌──────────────┼──────────────┐
                  │              │              │
                  ▼              ▼              ▼
             Git Manager    Build Manager   Runtime Manager
                  │              │              │
                  └──────────────┼──────────────┘
                                 ▼
                           Process Manager
```

Verify that:

- TUI does not contain business logic.
- MCP does not contain business logic.
- The daemon owns authoritative runtime state.
- Infrastructure operations use existing managers.
- Task scheduling is centralized.
- Application Core remains interface-independent.

Identify architectural violations.

Fix only those that create real correctness, safety, or maintainability problems.


# 33. Defect Prioritization

Classify discovered issues.

## Critical

- Data loss
- Unauthorized operations
- Wrong database target
- Killing unrelated processes
- Duplicate daemon ownership
- Severe security vulnerabilities

## High

- Broken workflow execution
- Incorrect task state
- Deadlocks
- Process leaks
- Incorrect dependency ordering

## Medium

- Incorrect diagnostics
- Missing error context
- UI state inconsistencies
- Performance regressions

## Low

- Minor UX issues
- Documentation gaps
- Non-critical formatting problems

Fix Critical and High issues first.
