# PART D — MIGRATION PRESETS

## 16. Named Migration Presets

Implement reusable named migration presets.

Initial presets:

- Status
- Update
- Reset Local Database

Presets must be configuration-driven.

Do not hard-code a single Liquibase command for every service.

## 17. Liquibase Update Preset

Support the command equivalent of:

```bash
mvn liquibase:update -Dliquibase.contexts=sql,data,onlyDev
```

Represent executable and arguments structurally.

The contexts must be configurable.

## 18. Liquibase Reset Preset

Support the command equivalent of:

```bash
mvn liquibase:dropAll liquibase:update -Dliquibase.contexts=sql,data,onlyDev
```

Represent this as a named, explicitly destructive operation.

Example conceptual configuration:

```toml
[migration.presets.reset_local]
provider = "liquibase"
execution_mode = "maven"
goals = ["liquibase:dropAll", "liquibase:update"]
contexts = ["sql", "data", "onlyDev"]
destructive = true
allowed_environments = ["local"]
```

Adapt this to the existing configuration schema.

Do not create an unrestricted command execution mechanism.

## 19. Destructive Migration Safety

This requirement is mandatory.

`liquibase:dropAll` can destroy database objects.

Before execution:

- Resolve the actual configured database target.
- Validate environment classification.
- Reject unknown or unauthorized targets.
- Do not assume localhost means a local database.
- Identify all affected database targets.
- Display the destructive operation clearly.
- Require trusted authorization through Application Core.
- Require explicit user confirmation for each distinct database target or an equivalent trusted batch authorization covering the exact target set.
- Revalidate authorization and targets immediately before execution.
- Do not automatically retry.
- Do not claim rollback after cancellation.

Do not allow a template to grant itself authorization merely by declaring `allowed_environments = ["local"]`.

## 20. Shared Database Coordination

Multiple services may use the same database.

Use the existing Migration Manager's database-target coordination.

Do not run conflicting migrations concurrently.

Do not automatically release Liquibase locks.

Do not assume a combined `dropAll` and `update` operation is atomic.

## 21. Migration Preset Assignment

Allow assigning a migration preset to multiple selected backend services.

Presets define command behavior.

Each service must retain its own validated database target and migration configuration.

Do not copy database credentials into templates.
