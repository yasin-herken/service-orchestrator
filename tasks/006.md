# Goal

Implement the **Process Manager**.

This component is responsible for executing and managing all local operating system processes.

The Process Manager is the only layer that should know how to:

- spawn processes
- terminate processes
- monitor processes
- collect stdout/stderr
- track process lifecycle
- manage child processes
- detect exit status
- integrate with task cancellation

Everything else (Git, Maven, npm, Liquibase, Spring Boot, React, etc.) must use the Process Manager instead of spawning processes directly.

---

# Architectural Rule

Only the Process Manager may directly create OS processes.

Bad:

GitManager
→ Command::new(...)

Bad:

BuildManager
→ std::process::Command

Bad:

LiquibaseManager
→ tokio::process::Command

Correct:

GitManager
→ ProcessManager

BuildManager
→ ProcessManager

LiquibaseManager
→ ProcessManager

Application
→ ProcessManager

---

# Responsibilities

The Process Manager must provide:

- Spawn process
- Stop process
- Kill process
- Restart process
- Track PID
- Capture stdout
- Capture stderr
- Detect exit
- Process status
- Cancellation integration
- Graceful shutdown
- Cleanup

---

# Process Lifecycle

Support states such as:

```text id="p1"
Created
Starting
Running
Stopping
Stopped
Exited
Failed
Killed
```

Document valid state transitions.

---

# Process Handle

Create a strongly typed ProcessHandle.

It should expose operations such as:

- status()
- pid()
- stop()
- kill()
- wait()
- subscribe_logs()

Avoid exposing raw tokio process types outside this crate.

---

# Process Specification

Represent a process before execution.

Example concepts:

- executable
- arguments
- working directory
- environment variables
- timeout
- restart policy

Avoid using raw shell strings whenever possible.

Prefer structured arguments.

---

# stdout / stderr

Capture both streams independently.

Support:

- realtime streaming
- line-based consumption
- future log persistence

Do not merge stdout/stderr into a single String.

---

# Cancellation

Integrate with the Task Engine cancellation model.

If a task is cancelled:

Task
↓
ProcessManager
↓
SIGTERM
↓
timeout
↓
SIGKILL (if necessary)

Make the shutdown strategy configurable.

---

# Graceful Shutdown

Prefer graceful termination.

Only force-kill when necessary.

Document:

- SIGTERM behavior
- timeout
- SIGKILL escalation

---

# Restart

Support restart.

The restart operation should preserve process specification but create a new execution instance.

---

# Environment

Support custom environment variables.

Do not expose secrets through logs.

---

# Working Directory

Support configurable working directories.

Do not assume every command executes from the workspace root.

---

# Exit Information

Represent:

- exit code
- signal
- execution duration
- termination reason

---

# Process Registry

Maintain an in-memory registry.

Support:

- lookup by ProcessId
- lookup by ServiceId
- list running processes
- list all processes

---

# Log Streaming

Support subscribers.

Future consumers:

- Ratatui
- MCP
- Logging subsystem

Use async streams/channels.

---

# Multiple Processes

Support multiple concurrent processes.

The manager should comfortably handle dozens of processes simultaneously.

---

# Process Events

Emit events such as:

- ProcessStarted
- ProcessExited
- ProcessFailed
- ProcessKilled
- StdoutLine
- StderrLine

These events must be interface-independent.

---

# Thread Safety

The manager will be accessed concurrently.

Design shared state carefully.

Avoid unnecessary locking.

---
